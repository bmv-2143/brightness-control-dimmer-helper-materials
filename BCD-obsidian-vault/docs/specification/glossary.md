# Глоссарий спецификации BCD

Общий справочник языка исследования, решений, спецификации, Gherkin и плана тестирования. Начинать знакомство с результатами удобнее с [workflow-progress](workflow-progress.md); сюда можно возвращаться за расшифровкой слова или кода. Местные определения сохранены рядом с правилами и формулами и должны совпадать по смыслу со справочником.

Глоссарий не утверждает требований, архитектуру или результаты испытаний. Числа ниже поясняют уже записанные формулы; нормативное поведение задают принятые DEC и RULE. Конкретные решения, вопросы, правила, сценарии и проверки остаются в своих документах и здесь не дублируются.

## Продукт и документы

| Термин | Простое объяснение и источник точного контекста |
|---|---|
| BCD | Brightness Control & Dimmer — приложение управления яркостью и дополнительным затемнением. [Назначение](product-specification.md#назначение-и-границы). |
| Legacy, AS-IS | Старое приложение и обнаруженное существующее поведение: «как есть». Код, заявленный комментарий и физический результат устройства — разные свидетельства. [Инвентаризация](legacy-behavior-inventory.md). |
| Rewrite, TO-BE | Переписывание и желаемое поведение: «как должно быть». Оно определяется решениями, а не автоматически копируется из Legacy. [Журнал](behavior-decisions.md). |
| Capability → Feature → Legacy Behavior | Крупная пользовательская возможность → логически связанная функция → конкретное поведение Legacy. Техническое наблюдение не становится Feature ради покрытия кода. [Карта](legacy-behavior-inventory.md). |
| Rule, пример | Нормативное правило принятого поведения и конкретный проверяемый случай его применения. Вместе они задают условия приёмки. [Карта нормативных документов](product-specification.md#карта-продукта). |
| Discovery, coverage, gap | Исследование, охват источников и пробел знания. Discovery coverage не процент покрытия кода тестами и не доказательство исчерпывающей полноты. [Покрытие](discovery-coverage.md). |
| Статическое исследование, runtime, platform feasibility | Анализ файлов без запуска, поведение работающего приложения/устройства, возможность выполнить поведение при ограничениях платформы. Статика не подтверждает runtime; feasibility остаётся будущей проверкой. [Пробелы](discovery-coverage.md), [TEST-047](test-plan.md#дополнительные-проверки-и-characterization). |
| Evidence, provenance | Свидетельство и его происхождение: версия, путь, строки, точный символ и цепочка вызовов. [Каталог](source-evidence.md). |
| Traceability | Прослеживаемость: связь факта с решением, правилом, сценарием и будущей проверкой. [Таблица связей](traceability.md). |
| Review | Проверка человеком результатов и решений. Возможность review не требует предварительного подтверждения всех ясных решений агента. [Статусы](behavior-decisions.md). |
| Template, prototype, dummy | Стартовый экран нового проекта, архивный опытный UI и фиктивные данные. Они не задают архитектуру переписывания. [Границы](product-specification.md#платформенные-и-нефункциональные-границы). |

## Идентификаторы и нумерация

| Семейство | Значение, формат и где находятся записи |
|---|---|
| CAP-001 | Capability — крупная возможность продукта. `CAP-` и три цифры. [Инвентаризация](legacy-behavior-inventory.md). |
| FEAT-001 | Feature — функция внутри Capability. `FEAT-` и три цифры; не обязательно отдельный файл или один Gherkin Feature. [Инвентаризация](legacy-behavior-inventory.md). |
| LB-001 | Legacy Behavior — карточка конкретного поведения старой версии. `LB-` и три цифры. [Карточки](legacy-behavior-inventory.md#карточки-поведения). |
| DEC-001 | Decision — запись продуктового решения, включая нерешённую ветвь. `DEC-` и три цифры. [Журнал](behavior-decisions.md). |
| Q-001 | Question — вопрос человеку с вариантами, причиной и ответом, если он получен. `Q-` и три цифры. [Вопросы](behavior-decisions.md#вопросы-человеку). |
| RULE-001 | Нормативное правило новой версии. `RULE-` и три цифры. [Расположение](traceability.md#где-находятся-rulescn). |
| SCN-001 | Scenario — определение Gherkin-сценария или Scenario Outline. `SCN-` и три цифры. Один Outline имеет один SCN, хотя Examples содержит несколько строк. [Связи](traceability.md). |
| TEST-001 | Запланированная проверка. `TEST-` и три цифры; не существующий, исполняемый или пройденный тест. Запись может предусматривать разные среды/запуски. [План](test-plan.md). |
| E01 | Локальный код свидетельства Legacy: `E` и две цифры без дефиса. «E-номера» в тексте имеют именно этот формат, не `E-01`. [Каталог](source-evidence.md). |
| P01 | Код официального источника по платформе: `P` и две цифры без дефиса. Не приоритет P0/P1/P2. [Источники](source-evidence.md#платформа-проверено-по-официальным-источникам). |
| G01 | Код открытого discovery/runtime gap: `G` и две цифры без дефиса. Не Given или SCN. [Пробелы](discovery-coverage.md#открытые-discoveryruntime-gaps). |
| ID, per-ID, UUID | Идентификатор; отдельно для каждого экземпляра; формат уникального идентификатора, встречающийся в исследовании кода. UUID не формат CAP/SCN. [Доказательства](source-evidence.md), [widgets](features/controls-and-widgets.md). |
| Диапазоны ID | `LB-001–LB-003` включает три номера. ID стабильны, не выводятся из filenames, не перенумеровываются/переиспользуются. Объединение требует сохранённой таблицы соответствий. [Связи](traceability.md). |

Семейства обозначают разные сущности: одинаковые цифровые части не доказывают связь. Количество SCN — число определений, а не строк Examples или запусков; количество TEST не число пройденных тестов. Текущие объёмы — в [workflow-progress](workflow-progress.md).

## Решения, основания и уверенность

Основание факта, признаки, confidence, тип решения и статус автора — независимые поля. Подтверждение идеи исследования не делает её принятой функцией; решение агента не повышает уверенность в Legacy. Источники: [карточки LB](legacy-behavior-inventory.md#карточки-поведения), [журнал DEC](behavior-decisions.md).

| Обозначение | Значение |
|---|---|
| KEEP | Сохранить значимое поведение; не обязательно его реализацию. |
| CHANGE | Изменить поведение с явным основанием и описанием результата. |
| DROP | Исключить поведение/механизм в указанном объёме. Удаление обходного механизма само по себе не отменяет обслуживаемую возможность. |
| INVESTIGATE, UNKNOWN | Оставить ветвь для исследования/решения. UNKNOWN — синоним INVESTIGATE, не отдельный тип. |
| ADOPTED_BY_AGENT | Агент принял решение в делегированных полномочиях; человек может его пересмотреть. |
| CONFIRMED_BY_USER | Пользователь явно подтвердил указанный объём. Это не подтверждение соседних решений или принятие исследовательского кандидата как функции. |
| PENDING_USER | Требуется ответ человека по нерешённой части; эта часть исключена из принятых RULE/Gherkin. Для частично принятого DEC подтверждённый объём и его RULE указаны отдельно. Молчание не ответ. |
| CLOSED_BY_USER | Статус вопроса Q: пользователь ответил в указанном объёме. Не статус DEC и не подтверждение реализации/внешнего сервиса. [Q-002](behavior-decisions.md#q-002--коммерческая-модель). |
| SUPERSEDED | Решение заменено последующим; история и связь с заменой сохраняются. |
| OBSERVED_IN_CODE | Прямо подтверждено кодом. Это статическое исследование, не запуск приложения. |
| INFERRED | Вывод из связей/цепочки действий, а не прямое подтверждение конкретного результата. |
| UNCERTAIN | По доступным свидетельствам утверждение не установлено. |
| Confidence: HIGH / MEDIUM / LOW | Уверенность в конкретном утверждении LB: прямой код и связанный вход / вывод или конфликт путей / недостаточно оснований. HIGH для API-запроса не доказывает физический эффект. |
| RUNTIME_VALIDATION_REQUIRED, RV | Нужна проверка на работающей системе/устройстве. |
| POSSIBLE_BUG, PB | Кандидат ошибки, не диагноз выполненной программы. |
| PARTIAL_IMPLEMENTATION, PI | Обнаружена неполная реализация заявленной возможности. |
| DEAD_OR_UNREACHABLE_CANDIDATE, DC | Кандидат неиспользуемого/недостижимого кода. Проверяются manifest, косвенные и внешние входы. Признак не доказывает недостижимость. |
| OBSOLETE_PLATFORM_BEHAVIOR_CANDIDATE, OC | Кандидат устаревшего платформенного механизма; назначение и современная замена рассматриваются отдельно. |
| «просмотрено» / «исключено с обоснованием» / «требует дальнейшей проверки» | Статусы охвата источников, не статусы DEC или результаты тестов. Точный объём/причина указываются в [coverage](discovery-coverage.md). |

## Яркость, формулы и состояние

Различаются условная шкала BCD, системная настройка и физический свет экрана. Общие определения — в [product-specification](product-specification.md#термины-и-общий-контракт); нормативные формулы — в [brightness-and-dimming](features/brightness-and-dimming.md); исторические варианты — в [E01–E06](source-evidence.md).

| Термин или запись | Как понимать |
|---|---|
| p, percent, значение BCD | Целая пользовательская цель по условной шкале BCD. «% BCD» не измеренный процент физической luminance. Auto — отдельный режим. |
| raw, OS raw, OSraw | Число `Settings.System.SCREEN_BRIGHTNESS`. Нормативные расчёты используют шкалу1..255. Число и успешное чтение настройки не доказывают световой эффект. |
| M, M255 | В Legacy M — найденный верхний предел шкалы из `PowerManager.BRIGHTNESS_ON` с fallback255. M255 означает M=255. Не аппаратная калибровка; TO-BE не требует старого reflection. |
| alpha, opacity | Непрозрачность. Формула может сначала дать байтовый alpha0..255, затем долю после деления на255. Widget opacity в процентах — оформление widget, а не dimmer overlay. |
| Paint alpha, params.alpha | В Legacy разные множители: непрозрачность рисования и окна. Новые внутренние классы этим не предписываются. [E06](source-evidence.md). |
| manual, positive, negative, dim/dimming | Ручной режим; неотрицательный p там, где правило говорит p>=0; p<0; дополнительное затемнение чёрным overlay. Слово positive в кратких описаниях не исключает ноль автоматически. |
| Auto, automatic brightness | Автоматический режим ОС, не максимальная яркость, число ноль или обещание точной физической яркости. |
| mode, MODE_AUTO, MODE_AUTOMATIC, MODE_MANUAL | Краткие обозначения режимов. Полные константы — `Settings.System.SCREEN_BRIGHTNESS_MODE_AUTOMATIC`/`SCREEN_BRIGHTNESS_MODE_MANUAL`; `SCREEN_BRIGHTNESS_MODE` — настройка режима. MODE_AUTO не точное имя Android API. |
| Sentinel, MIN_VALUE | Специальное число-маркер; в Legacy `Integer.MIN_VALUE` обозначает Auto. Не допустимый p и не число для шага. |
| floor, integer division | Округление вниз и целочисленное деление; в активной формуле с неотрицательным числителем совпадают. floor(12.75)=12; не helper round. |
| round, Math.round | Округление к ближайшему целому; для используемых неотрицательных аргументов половина вверх. Например63.75→64. Какая операция применяется, определяет конкретная формула. |
| abs, min, max | Модуль, минимум и максимум. abs(p) в вычислении alpha не превращает отрицательную цель в положительную команду. |
| clamp, wrap | Ограничить ближайшей границей; перенести через противоположную границу. Принят clamp; wrap упомянут как альтернатива, не требование. |
| p', step, signedStep, base | Результат шага, его величина для данной поверхности, шаг со знаком и исходное число операции. При выходе из Auto base определяется актуальным raw по правилу. |
| progress, index | Позиция slider/индекс выбора, не автоматически p или длительность. Legacy progress=p+75; индекс таймера пересчитывается в длительность. Это не требование UI-архитектуры. |
| Floor, minimum, safety minimum | По контексту операция floor выше или защитный предел команды. В Legacy MIN_SAFE_BRIGHTNESS_PERCENT=5, minimum=M*5/100 с integer division; при M255 raw12. В новой спецификации p<=5 также даёт raw12, включая boot restore RULE-043. Не raw5 и не гарантированные5% физической яркости. Отдельный boot minimum10 не принят. [Историческая причина](features/brightness-and-dimming.md#назначение-защитного-порога--дополнение-к-rule-002-и-rule-003). |
| Luminance, backlight, attenuation | Физическая яркость, подсветка, ослабление света/изображения. Raw и alpha сами по себе не измеряют эти величины. |
| Calibration, per-device diagnosis | Калибровка/проверка конкретного устройства. Идея проверки низких значений с подтверждением и возвратом — кандидат DEC-030/TEST-052, не принятое обходное разрешение floor. [Граница идеи](test-plan.md#граница-будущей-диагностики-устройства). |
| requested state, goal, target | Последняя принятая пользовательская цель. Target здесь не targetSdk. |
| observed state, actual, readback | Прочитанные режим/raw ОС и факт активности/приостановки окна; readback — чтение настройки после запроса. Физический результат проверяется отдельно. |
| State, cache, saved, previous | Состояние по контексту, копия данных, сохранённое и предыдущее. Старый `BrightnessState` — конкретный класс. Название состояния/копии не доказывает актуальность ОС. |
| sync, own-write echo, external change | Синхронизация с внешними изменениями; уведомление о собственной записи BCD; независимое внешнее изменение. Причины не взаимозаменяемы. |
| Apply, success, denial, partial failure | Применение, подтверждённый успех, отказ и частичный отказ. Запрос отличается от результата; при partial failure часть действий могла выполниться. [Ошибки](features/permissions-and-exclusions.md). |
| Rollback, recovery, safety | Возврат к прежнему состоянию, восстановление и защита управления. Обычный отказ не обещает скрытого rollback; надёжность будущей диагностики не подтверждена. [Состояние](features/state-and-recovery.md), [TEST-052](test-plan.md#граница-будущей-диагностики-устройства). |

## Интерфейс, настройки и покупки

Источники: [controls-and-widgets](features/controls-and-widgets.md), [state-and-recovery](features/state-and-recovery.md), [help-and-constraints](features/help-and-constraints.md), [Q-002](behavior-decisions.md#вопросы-человеку).

| Термин | Значение |
|---|---|
| Surface, main, panel | Место выполнения команды: панель, notification или widget; основной экран/панель; сама панель. Не отдельные режимы яркости. |
| Preset, fixed, editor | Сохранённое значение кнопки, команда установленного значения, редактирование настройки. Сохранить preset не значит применить свет. «Старый preset» в обзоре шага из Auto — неточное обозначение прежней числовой цели BCD, не актуального raw ОС. |
| Tap/click, long tap/click, drag, release | Нажать, удержать, переместить ползунок, отпустить. Это действия, не имена обязательных UI-классов. |
| User/programmatic event | Пользовательское действие/программное отражение состояния. Отражение состояния на slider не новая команда. |
| Save, Done, Cancel, Back, Close, Empty Done | Сохранить, завершить ввод, отменить, вернуться, закрыть, завершить без ввода. Это смыслы действий, не обязательные английские подписи UI. |
| Notification, shade, controls, notice, icon | Уведомление, панель уведомлений, управляющие кнопки, извещение об активной работе, значок. Отключение controls не тождественно остановке dimming. |
| Channel, importance HIGH/LOW/MIN | Канал и его важность. HIGH/LOW здесь не confidence LB и не приоритет теста. Учитывается пользовательская настройка канала. |
| Widget, instance, host, launcher/home, keyguard | Виджет, экземпляр, размещающее его приложение, домашний экран, экран блокировки. Историческая категория keyguard не гарантирует современное размещение. |
| A/B, stepA/stepB, tapA/tapB | Два widget-экземпляра и их шаги/нажатия. A здесь не среда Android/platform плана. |
| Visibility, hidden, row/group, hide all | Видимость элемента, скрытый элемент, ряд/группа, скрытие всех групп. Не остановка фонового действия. |
| Pref/preferences, key, default, fallback | Настройка, ключ, значение по умолчанию, запасной вариант. Конкретные defaults задаются LB/RULE, не названием термина. |
| SharedPreferences, named prefs, WIDGET_PREFS | Android-хранилище ключ–значение, отдельный именованный набор, краткое описание widget-настроек. WIDGET_PREFS не гарантирует точное имя preference key. [E19–E20](source-evidence.md). |
| Global, individual, per-widget | Общая настройка, настройка экземпляра, отдельно для каждого widget. Старый глобальный ключ и per-ID различаются. |
| Persistence, restoration, migration | Сохранение между открытиями, восстановление, перенос совместимых старых настроек. Неизвестное значение не становится валидным при копировании. |
| Atomic, idempotent, replay, dedup | Сохранение целиком, повтор с тем же эффектом, повтор операции, исключение дубликата. Идемпотентность значения на границе не исключает rearm от новой negative-команды. |
| Locale, en/ru, EN/RU/en_US, fallback language | Языковая настройка, коды английского/русского, английская локаль США, запасной язык. Не язык ключевых слов Gherkin. |
| Accessibility, labels, hierarchy | Доступность пользователям, обозначения элементов, дерево UI. Не старый AccessibilityService для распознавания приложения. |
| Share, chooser, receiver | Поделиться, системный выбор получателя, приложение-получатель. Receiver здесь отличается от BroadcastReceiver. |
| Premium, entitlement, paywall, availability | Платные возможности, право на них, ограничение платного доступа, доступность операции. «Editor доступен» не утверждает бесплатность. |
| Бессрочный Premium, lifetime, non-consumable | Не расходуемое покупкой/использованием право на прежний набор возможностей. Это не будущая подписка; действительность покупки проверяется отдельно. [RULE-036](features/monetization.md). |
| Subscription, подписка | Доступ по ограниченному сроку и условиям продукта; в первой версии только задел для будущих новых функций, не продаваемое предложение. [RULE-040](features/monetization.md). |

## Gherkin и параметры примеров

`.feature` — читаемые примеры, не исполняемые тесты. [Связи](traceability.md), [будущая связь с Kotlin](test-plan.md#минимальный-будущий-acceptance-driver).

| Запись | Значение |
|---|---|
| Gherkin, `.feature`, `# language: en` | Формат, файл, выбор английских ключевых слов. Описания/шаги русские. Один файл содержит один Feature. |
| Feature, Rule | Gherkin-группа сценариев и группа по правилу. Файл может объединять несколько FEAT; Rule содержит RULE ID в названии. |
| Scenario, Given, When, Then, And, But | Сценарий; исходные условия; действие; результат; продолжение; продолжение с противопоставлением. Это декларативные шаги, не готовые вызовы кода. |
| Scenario Outline, Examples, `<p>` | Шаблон, таблица вариантов, подстановка из столбца. Каждый ряд — пример, не новый SCN ID. |
| `@FEAT-001`, `@SCN-001` | Теги связи; не регистрация JUnit и не доказательство исполнения. |
| Parser, validation, Cucumber, glue, driver | Разборщик, проверка, возможный исполнитель Gherkin, привязка шагов к коду, посредник действий. Parser недоступен, syntax проверен вручную; интеграция/driver не созданы. |
| IR, JSON IR, generator, mutator, SwarmForge | Промежуточное представление/его JSON-форма, генератор, изменение вариантов, названная возможная инфраструктура. Ничего из этого сейчас не создано/принято обязательным. |

Имена столбцов Examples — локальные параметры Outline, не preference keys или поля будущих Kotlin-классов. Полный смысл определяется его Given/When/Then:

| Столбцы | Значение |
|---|---|
| `p`, `raw`, `alpha`, `step` | Цель, системное число, непрозрачность, шаг. Единицы alpha задаёт текст сценария. |
| `sync`, `mode`, `auto`, `opacity` | Синхронизация, режим, настройка Auto по контексту widget, оформление widget. Auto в столбце не всегда режим ОС. |
| `before`, `after`, `old`, `value`, `input` | Исходное, итоговое, прежнее, проверяемое значение, ввод. Тип не угадывается из одного имени. |
| `kind`, `source`, `surface`, `action`, `option` | Вид настройки, источник изменения, поверхность управления, действие, вариант настройки. |
| `display`, `panel`, `result` | Отображение, состояние панели, результат. |
| `global`, `individual` | Общий старый параметр/параметр экземпляра при миграции. |
| `api`, `write`, `overlay`, `permission`, `request`, `availability`, `failure` | API level, WRITE_SETTINGS grant, overlay grant/окно по шагу, доступ, запрос, доступность, отказ. Overlay permission и активность окна различаются. |
| `receiver`, `locale`, `language` | Получатель Share, исходная локаль, язык UI. |
| `answer` | Ответ детектора foreground-приложения в данном Outline, не ответ человека на Q. |
| `condition`, `delivery`, `duration`, `times` | Условие, доставка события, длительность, временные точки. Основание отсчёта задаёт сценарий. |

| CI, CLI, IDE, MCP | Автоматические проверки интеграции, командная строка, среда разработки, интерфейс инструментов агенту. Упоминание не означает выполнение. |

| ah, text/plain | Исторический параметр URL ссылки Share и тип передаваемого обычного текста. Наличие ah в Legacy не приписывает ему неизвестное назначение. [E36](source-evidence.md), [DEC-026](behavior-decisions.md). |
| URL, SDK key, signature/signing | Адрес, ключ SDK, подпись/подписание сборки или покупки по контексту. Реальные секреты не копируются; имя key не доказывает доверие. |
| true/false, on/off, enabled/disabled | Булевы значения/состояние настройки. Enabled preference не grant. |
| null, absent/noID, invalid, unknown | Нет значения, нет записи/ID, недопустимо, неизвестно. Не ноль/false. Unknown detector не тип решения UNKNOWN. |
| AND/&&, OR/`\|\|` | Логическое «и»/«или», вертикальные черты Markdown экранируются. Ошибочный OR Legacy не новый контракт. |
| `→`, `=`, `<=`, `>=`, `×`, `/` | Результат, равенство/присваивание по контексту, включительные границы, умножение, деление. Между ID `/` лишь разделитель. |
| `a..b`, `[a,b]`, `a–b`, `%` | Диапазон включительно и процент в указанной шкале. p, raw, opacity различаются. |
| t, now, at0/at1h, now+duration | Время, текущее время, относительный момент, момент истечения. Отсчёт задаёт сценарий; t не путь T/. |
| ms, s, min, h, dp | Миллисекунды, секунды, минуты, часы, UI-единицы независимо от плотности. Min API — минимум; min в формуле — минимум. 3h/1h30 — три часа/час тридцать минут. |
| TODO, candidate, partial, obsolete/dead | Незавершённое намерение, кандидат, неполнота, устаревание/недостижимость. Комментарий/UI-текст не подтверждённое выполнение. |

Точные имена API, классов, методов, resources и preference keys не переводятся и не получают нового смысла: их контекст/версия находятся в E-свидетельствах. Сокращённые MODE_AUTO/WIDGET_PREFS не следует переносить в код как проверенные имена API. Все числовые defaults и поведенческие значения остаются в LB/DEC/RULE.

## Как поддерживать справочник

1. Новый существенный термин пояснить при первом использовании в контексте и добавить сюда со ссылкой на точный источник. Существующие местные определения сохранять.
2. При изменении смысла согласованно обновить глоссарий, местные определения и затронутые связи. Изменение поведения оформить через DEC с историей и обновить зависимые RULE/SCN/TEST. Глоссарий не основание нового требования.
3. Каждый новый документ спецификации должен ссылаться сюда. В `.feature` достаточен короткий комментарий после первой строки `# language: en`.
4. Перед коммитом сверить употребление/неоднозначности, ссылки на файлы/разделы, стабильные ID. Ручная семантическая проверка не заменяет parser validation или runtime-тесты.

Правило закреплено в [AGENTS.md материалов](../../../AGENTS.md#поддержание-глоссария). Для текущего справочника проверены все Markdown-файлы `docs/specification/` и пять `features/*.feature`; новых требований/статусов эта работа не вводит. При следующем расширении материалы и справочник проверяются вместе.

## Уточнение результата восстановления —2026-10-08

Для [RULE-047](features/state-and-recovery.md) полный/частичный отказ или
неподтверждённое применение — результат одной операции с причиной и доступным
observed mode/raw. Причины не требуют отдельных подсистем/семи состояний.
Ошибка readback не означает raw0; частичное применение не обещает rollback.

## Резервная яркость после отказа Auto —2026-10-08

[Резервные25%](features/state-and-recovery.md) по RULE-048 — одна попытка manual25/raw63
для актуальной Auto boot цели при установленном отказе Auto и доступной ручной
записи, всегда без overlay. Policy Auto остаётся сохранённой. Это не initial25
настройки fixed policy, не новая настройка и не подтверждение физической видимости.

## Ограничение подтверждения открытия —2026-10-08

DEC-012 CONFIRMED_BY_USER только для обычного открытия RULE-023;
recreation и миграция RULE-024 остаются предложением. Повторная доставка —
повтор той же операции системой без нового выбора пользователя; новое явное
нажатие не дубликат. Crash — аварийное завершение из-за необработанной ошибки;
остановка процесса ОС из-за памяти сама по себе не ошибка приложения.
[Точные примеры и статус предложений](../workflows/legacy-differences-review.md).

## Объём подтверждений opacity/повтордоставки —2026-10-08

Принята единая итоговая opacity; это не сохранение старого визуального эффекта
при импорте preset. Миграция — преобразование/сохранение настроек при переходе
Legacy→новая версия, а recovery — продолжение актуальной сессии.
Повтордоставка подтверждена, forced crash restart отдельно ещё открыт.
[Объём и незакрытые случаи](../workflows/legacy-differences-review.md).

## Подтверждение recovery/миграции —2026-10-09

DEC-012 теперь подтверждён также для RULE-024: предыдущие ограничения
подтверждения2026-10-08 исторические. Перенос presets сохраняет числа;
не обещает сохранить старую итоговую opacity. Собственный forced crash restart
убирается по DEC-015, допустимое восстановление сервиса ОС — отдельный случай.
[Принятый объём](../workflows/legacy-differences-review.md).

## Default шкала и нестандартный OEM —2026-10-09

Default255 — документированный базовый диапазон системной настройки, не
аппаратный максимум дисплея. Нестандартная OEM шкала — сообщённое отклонение
прошивки; реестр отмечает источник/неопределённость, не подтверждает новую версию.
Compatibility requirement принято, способ и перенос workaround отдельно
проверяются/согласуются. [Реестр](source-evidence.md#реестр-нестандартных-шкал-и-обходов-2026-10-09).
