CAP-004. Reboot-контракт Q-001 принят частично: Auto default, три политики включая «Заданную яркость», опциональный overlay с выключенным default в «Последнем режиме BCD». 2026-10-06 подтверждены момент overlay после первой разблокировки и сохранение исходного окончания таймера через reboot; они задаются RULE-041–RULE-042 ниже. Числовые ограничения, параметры заданной яркости, момент записи системной яркости и clock/recovery ещё открыты в [подготовке](../../workflows/full-rewrite-preparation.md). Нет обещания перезапуска после force-stop/system stop/crash.

Deadline — исходный момент окончания, сохраняемый также через reboot по RULE-042.
Внутри одной загрузки допустим монотонный отсчёт; его значение нельзя буквально
перенести в следующую загрузку. Способ хранения/сопоставления времени и реакция
на изменение часов ещё требуют технического решения. Примеры с часами предполагают
достоверное время без его изменения. После перезапуска процесса с просроченным
deadline не начинать новый полный срок. Таймер не требует новых exact-alarm grants
и debug ускорения; точная секунда исполнения не обещается. Предлагаемые тесты
отдельно проверяют virtual time логику и реальную доставку/ограничения ОС.
