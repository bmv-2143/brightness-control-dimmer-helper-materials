# Состояние, таймер и защитное восстановление

[Глоссарий: термины и обозначения](../glossary.md). Местные пояснения сохраняют тот же смысл.

CAP-004. Reboot-контракт Q-001 закрыт пользователем 2026-10-08 в объёме RULE-041–RULE-048: три boot policy, единый процентный minimum5, fixed5..100/initial25, опциональный overlay после первого unlock/default off в Last, исходный timer deadline, ранняя защита, недостоверный срок и упрощённый отказ/partial с резервной попыткой25 при установленном отказе Auto. Техническая реализуемость, алгоритм часов и ограничения ОС остаются для плана/проверок, не нерешённые продуктовые параметры. Нет обещания перезапуска после force-stop/system stop/crash. [История согласования](../../workflows/full-rewrite-preparation.md).

Deadline — исходный момент окончания, сохраняемый также через reboot по RULE-042.
Внутри одной загрузки допустим монотонный отсчёт; его значение нельзя буквально
перенести в следующую загрузку. Способ хранения/сопоставления времени и реакция
на изменение часов требуют технического решения в рамках принятого RULE-046. Примеры с часами предполагают
достоверное время без его изменения. После перезапуска процесса с просроченным
deadline не начинать новый полный срок. Таймер не требует новых exact-alarm grants
и debug ускорения; точная секунда исполнения не обещается. Предлагаемые тесты
отдельно проверяют virtual time логику и реальную доставку/ограничения ОС.

## Объём подтверждения открытия —2026-10-08

Принят RULE-023/DEC-012: обычное первое/повторное открытие само не меняет
mode/raw/overlay, не повторяет сохранённую команду и не запускает новый срок.
Действующий overlay остаётся; прекратившийся не показывается как действующий.
Recreation/миграция RULE-024 и forced crash restart DEC-015 ещё на review; повтордоставка RULE-025/DEC-014 принята следующим ответом2026-10-08.
SCN-031/TEST-031 относятся к принятому открытию; SCN-032/TEST-032/TEST-046
не утверждены этим ответом. Reboot-контракт подтверждён отдельно.

## Подтверждение повтордоставки —2026-10-08

Принят RULE-025/DEC-014: повтор той же операции не создаёт второго эффекта
и не меняет исходный deadline. SCN-033/TEST-033 — будущая проверка этого
контракта, не обещание перезапуска при любом завершении процесса.
Принудительный alarm+kill после crash (DEC-015) отдельно не подтверждён.
Recreation/миграция RULE-024 остаются отдельным предложением.

## Подтверждение оставшихся пунктов —2026-10-09

Приняты recovery/миграция RULE-024 и удаление forced crash restart DEC-015.
При recreation действующей сессии сохраняются актуальная цель/исходный deadline,
проверяются sync/grants/exclusions; просроченный overlay не показывать даже кратко.
Это не обход force-stop и не повтор сохранённого preset при обычном открытии.
При upgrade валидные настройки и числа negative presets сохраняются;
нераспознаваемое поле получает свой default, неоднозначность не включает overlay.
Численный перенос может усилить затемнение на API31+; однократное краткое
сообщение принято. Premium/restore остаются подтверждёнными отдельно.

## Область raw примеров после DEC-001 —2026-10-09

Принят default255 с требованием совместимости нестандартных шкал; raw12/63
в этом документе — default примеры, не доказательство диапазона любого OEM.
Способ учёта нестандартной шкалы и сохранения процентной защиты выбрать после
проверки актуальности обхода, без автоматического переноса reflection.
[Контракт шкалы](brightness-and-dimming.md#default255-и-совместимость-2026-10-09).

## Подробное согласование таймера и защитной последовательности —2026-10-12

[Принятые17 случаев](../timer-and-safety-cases.md) раскрывают RULE-026–RULE-029.
DEC-016 подтверждён; DEC-017 подтверждён для отрицательных сессий, действие при
положительной manual яркости остаётся открытым. Включённая настройка не означает
активный отсчёт; завершение/cancel не выключает настройку. Save изменённой active
duration начинает новый срок, отмена draft не меняет исходный deadline.
Случай12 подтверждает timer семантику exclusions, не всю группу5.
Реализация, Android испытания и макет этим согласованием не утверждены.
