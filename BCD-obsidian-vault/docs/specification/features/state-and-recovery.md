# Состояние, таймер и защитное восстановление

[Глоссарий: термины и обозначения](../glossary.md). Местные пояснения сохраняют тот же смысл.

CAP-004. Reboot-контракт Q-001 закрыт пользователем 2026-10-08 в объёме RULE-041–RULE-048: три boot policy, единый процентный minimum5, fixed5..100/initial25, опциональный overlay после первого unlock/default off в Last, исходный timer deadline, ранняя защита, недостоверный срок и упрощённый отказ/partial с резервной попыткой25 при установленном отказе Auto. Техническая реализуемость, алгоритм часов и ограничения ОС остаются для плана/проверок, не нерешённые продуктовые параметры. Нет обещания перезапуска после force-stop/system stop/crash. [История согласования](../../workflows/full-rewrite-preparation.md).

Deadline — исходный момент окончания, сохраняемый также через reboot по RULE-042.
Внутри одной загрузки допустим монотонный отсчёт; его значение нельзя буквально
перенести в следующую загрузку. Способ хранения/сопоставления времени и реакция
на изменение часов требуют технического решения в рамках принятого RULE-046. Примеры с часами предполагают
достоверное время без его изменения. После перезапуска процесса с просроченным
deadline не начинать новый полный срок. Таймер не требует новых exact-alarm grants
и debug ускорения; точная секунда исполнения не обещается. Предлагаемые тесты
отдельно проверяют virtual time логику и реальную доставку/ограничения ОС.
