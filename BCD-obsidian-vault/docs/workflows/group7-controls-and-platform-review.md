## Общий принятый контекст

Открытие/возврат, редактирование настройки и отражение состояния сами не команды
света и не начинают таймер заново. Эта семантика уже принята; случаи3/6/7/11
проверяют её на конкретных связях Legacy. Новая явная negative команда начинает
полную длительность заново, включая повтор того же значения; это тоже принято.
Технические разрешения для успешных команд предполагаются в будущей проверке,
кроме случая9, где отсутствие доступа составляет предмет случая.

Для редакторов и изменения платной видимости предполагается уже доступное право
по принятой коммерческой политике: Premium либо действительный доступ через игру.
Редактор Legacy может открыться и без права, но Ok тогда отключён; в настройках
редактирование быстрых кнопок отключено. Это не предложение изменить gates.
Названия новой версии смысловые, макет/формы сообщений пока не выбраны.
В Legacy Ok вызывает метод done; отдельная кнопка Save не требуется этим review.

## 1. Шаг останавливается на границе

**1. Предмет и статус.** Ограничение результата «+/−»: сохранить Legacy, DEC-004.

**2. Как в Legacy.** Общий расчёт ограничивает сумму диапазоном -75..100;
через противоположную границу не переносит. Основание E02/E08, история a9172acc.

**3. Предложение и почему.** Сохранить ограничение результата. Плюс у100
не должен неожиданно включать сильное затемнение. Это объяснение предложения,
не установленная авторская причина выбора границ.

**4. Экран и исходное состояние.** Главная панель, открытая значком BCD;
текущее значение98, шаг5. Отдельный вариант: текущее значение-73.

**5. Действия по порядку.** А: пользователь нажимает плюс дважды; BCD считает
каждый шаг. Б: пользователь при-73 нажимает минус дважды.

**6. Видимый результат.** А:100, затем100; Б:-75, затем-75. Панель остаётся
открытой. Повторный минус при-75 остаётся новой negative командой: если таймер
включён на3h, нажатие15:10 задаёт конец18:10, даже если число не изменилось.
Таймер здесь уже принятый контекст, не новый выбор группы7.

## 2. Начальные наборы кнопок остаются разными

**1. Предмет и статус.** Defaults main и общих быстрых кнопок: сохранить, DEC-006.

**2. Как в Legacy.** Код задаёт main8: -75,-50,-25,0,25,50,75,100;
общие4: -75,-25,25,75. Шаг обоих наборов5. E01/E09/E11/E17;
старые XML summary не совпадают с подписями, которые загружает код.

**3. Предложение и почему.** Сохранить два набора и шаги5; не унифицировать
их незаметно. Причина выбора именно этих чисел в просмотренной истории не установлена.

**4. Экран и исходное состояние.** BCD без сохранённых значений кнопок;
главная панель и раздел быстрых кнопок в настройках.

**5. Действия по порядку.** Пользователь открывает BCD, затем нажимает значок
настроек и читает значения четырёх быстрых кнопок и их шага.

**6. Видимый результат.** Видны указанные8/4 значения и шаги5; само чтение
не применяет их. Существующие валидные значения при обновлении не заменяются
defaults — это уже принятая миграция. Отдельные horizontal/vertical виджеты
«+/−» сохраняют свой default10, уже принятый в группе5.

## 3. Сохранение значения кнопки не применяет его

**1. Предмет и статус.** Редактор пресета: сохранить назначение, DEC-006;
устранение повторной команды при возврате следует из принятой навигации.

**2. Как в Legacy.** Длинное нажатие main кнопки открывает её редактор;
нажатие пункта быстрой кнопки в настройках открывает общий редактор.
Ok сохраняет настройку и закрывает экран. Но resume Main/Settings может
отправить старую яркость в service; нельзя объявить весь путь Legacy безэффектным.

**3. Предложение и почему.** Сохранять выбранную кнопку без команды света;
применять её лишь по явному нажатию. Не смешивать настройку кнопки с текущим светом.

**4. Экран и исходное состояние.** На main кнопка25, действующее значение50.
Для общего набора: в настройках третья быстрая кнопка25; действующее значение50.

**5. Действия по порядку.** А: пользователь долго нажимает main25, вводит75
цифровой клавиатурой и нажимает Ok. Б: пользователь открывает настройки,
нажимает третью быструю кнопку, вводит35 и нажимает Ok. Далее в каждом
независимом варианте пользователь явно нажимает изменённую управляющую кнопку.

**6. Видимый результат.** До явного управляющего нажатия свет остаётся50.
А: main показывает75, общая кнопка остаётся25; последующий tap применяет75.
Б: общий пресет35 отражается в настройках, доступном уведомлении и управляющем
виджете, main25 остаётся25; последующий tap применяет35.
После Ok возвращается экран, из которого открыт редактор.

## 4. Шаг панели и шаг общих быстрых кнопок редактируются отдельно

**1. Предмет и статус.** Настройка величины шага: сохранить, DEC-004/006.

**2. Как в Legacy.** Длинное нажатие main плюс/минус открывает один общий
для этих двух кнопок шаг; в настройках есть отдельный шаг уведомления/управляющего
виджета. Разные ключи; допустимы целые1..50. E08/E10/E11, история9393f1b6/bc2d20f6.

**3. Предложение и почему.** Сохранить независимые шаги1..50 и применение
после сохранения. История подтверждает намеренное добавление отдельной настройки,
но мотив верхнего предела50 не объясняет.

**4. Экран и исходное состояние.** Main открыт, текущее значение25;
оба шага5, быстрые controls доступны в уведомлении.

**5. Действия по порядку.** Пользователь долго нажимает main плюс, вводит2,
нажимает Ok. Затем в настройках нажимает шаг быстрых кнопок, вводит10,
нажимает Ok и возвращается Back на main. Пользователь нажимает main плюс,
затем плюс в уведомлении, затем main минус.

**6. Видимый результат.** Сохранение шагов оставляет25; явные нажатия дают
27→37→35. Уведомление и управляющий виджет используют один шаг10;
отдельные виджеты «+/−» сохраняют свои per-instance настройки группы5.

## 5. Числа вне диапазона редактора не сохраняются

**1. Предмет и статус.** Диапазон нового редактора: предложение сохранения,
DEC-006; согласование этого редактора не пересматривает общую шкалу группы1.

**2. Как в Legacy.** Preset принимает целое от прочитанного minimum до100,
default minimum=-75. Записи изменения этого minimum в production не найдены.
Шаг принимает1..50; ошибка оставляет экран открытым. E10.

**3. Предложение и почему.** Явно закрепить preset[-75,100], step[1,50];
не переносить недоказанную пользовательскую настройку minimum. Не подставлять
ближайшую границу вместо введённого недопустимого числа.

**4. Экран и исходное состояние.** Редактор main25 открыт длинным нажатием;
отдельный вариант — редактор main шага5 открыт длинным нажатием плюса.

**5. Действия по порядку.** Пользователь вводит-76 либо101 в preset,
или0 либо51 в step и нажимает Ok. Для следующей попытки пользователь очищает поле.

**6. Видимый результат.** Редактор остаётся открыт; сообщение сообщает
допустимый диапазон и возможность исправить число. Saved preset25/step5
сохраняется. -75/100 и1/50 допускаются по Ok. Форма сообщения ещё не выбрана;
цифровая клавиатура и читаемая ошибка уже приняты. Буквы/дроби не предлагаются
как обычный достижимый UI-пример Legacy.

## 6. Отмена, Back и пустое Ok оставляют прежнюю настройку

**1. Предмет и статус.** Выход из редактора без записи: сохранить, DEC-006;
отдельный вариант проверяет уже принятое истечение таймера при возврате.

**2. Как в Legacy.** Поле initially пустое, прежнее число — hint.
Cancel и пустой done вызывают finish без записи; собственного save по Back нет.
Но resume может повторить старую команду, как описано в случае3.

**3. Предложение и почему.** Сохранить отмену/пустой Ok без записи и исключить
световой эффект возврата. В частности, возврат не должен оживить истёкшее затемнение.

**4. Экран и исходное состояние.** А: редактор main25 открыт длинным нажатием.
Б: тот же редактор открыт15:59 при действующем-25 и конце таймера16:00;
редактируемая кнопка25 и действующее затемнение-25 — разные величины.

**5. Действия по порядку.** А: пользователь вводит75 и нажимает Cancel либо
системный Back; отдельная попытка — оставляет поле пустым и нажимает Ok.
Б: пользователь вводит75; в16:00 BCD получает возможность обработать конец
таймера; в16:01 пользователь нажимает Cancel.

**6. Видимый результат.** А: main с прежней кнопкой25, черновик не сохранён.
Б: при обработке срока BCD снимает затемнение и запрашивает Auto; редактор
сам не закрывается. В16:01 main показывает фактический результат Auto/отказа,
кнопка остаётся25; старое-25 не применяется снова. Нового срока нет.

## 7. Ползунок действует при перемещении, отражение состояния — без команды

**1. Предмет и статус.** Пользовательское изменение ползунка и его отображение:
сохранить различие Legacy, DEC-007.

**2. Как в Legacy.** Callback применяет изменившееся целое значение при
fromUser=true, до отпускания. Программный setProgress/animation не выполняет
ту же команду. Ранние оптимизации пропуска значений сняты b38b286d как неработающие ожидаемо.

**3. Предложение и почему.** Сохранить управление при перемещении и не
создавать команды из отображения. Не переносить задержки/пропуски автоматически
и не обещать физический результат каждого кадра.

**4. Экран и исходное состояние.** А: главная панель с видимым ползунком.
Б: панель отражает Auto; ОС изменяет яркость, пользователь ползунок не трогает.

**5. Действия по порядку.** А: пользователь перемещает ползунок к25 и
продолжает удерживать палец; BCD запрашивает25 до отпускания.
Б: ОС сообщает новое состояние, BCD обновляет подпись/положение ползунка.

**6. Видимый результат.** А:25 и соответствующий свет уже во время удержания,
панель открыта. Б: Auto сохраняется; отображение не переводит ОС в manual
и не выполняет повторный пресет. Взятие исходной базы шага из Auto уже принято отдельно.

## 8. Закрытие собственной панели после успешного выбора

**1. Предмет и статус.** close on select: сохранить назначение и defaultoff,
DEC-007. Речь только о собственной панели BCD.

**2. Как в Legacy.** Checkbox и настройка управляют одним ключом. Preset/Auto
вызывают finish при checked; slider/plus/minus не вызывают. E09/E11/E12;
Legacy закрывается после отправки, без проверки успешности — отказ отдельно в случае9.

**3. Предложение и почему.** Сохранить defaultoff и закрытие после успешного
preset/Auto при on; оставить панель при серии шагов/перемещении. Это действующее
различие, авторский мотив ограничения только двумя видами действий не установлен.

**4. Экран и исходное состояние.** Главная панель, опция включена;
для отрицательного варианта выбранная кнопка-25.

**5. Действия по порядку.** В независимых попытках пользователь нажимает
preset25, preset-25, Auto, плюс либо двигает ползунок; BCD успешно выполняет
команду. Ещё одна попытка: пользователь выключает опцию и нажимает25.

**6. Видимый результат.** При on после preset/Auto панель закрыта, после
плюса/ползунка открыта; при off после25 открыта. Применённый свет не отменяется
самим закрытием; отрицательная сессия и её срок продолжаются по принятым правилам.
Системная панель уведомлений не входит в эту настройку.

## 9. Отказ команды оставляет собственную панель доступной

**1. Предмет и статус.** Закрытие при отказе: явное отличие от Legacy, DEC-007
во взаимодействии с уже принятым отказом доступа.

**2. Как в Legacy.** Preset/Auto закрывают Main после отправки независимо от
подтверждённого эффекта. При отсутствии grants весь Main может быть недоступен;
такой путь Legacy не выдаётся за воспроизведённый сценарий.

**3. Предложение и почему.** При установленном отказе не закрывать панель
автоматически: пользователь должен видеть причину и иметь доступ к настройкам.
Это уточнение прежнего KEEP, а не точное сохранение всего Legacy пути.

**4. Экран и исходное состояние.** В новой версии пользователь открыл BCD
значком, close on select=true; WRITE_SETTINGS отсутствует, ОС в manual50.

**5. Действия по порядку.** Пользователь нажимает25; BCD обнаруживает
отсутствие доступа и объясняет его. Пользователь остаётся на панели и может
сам перейти к получению доступа.

**6. Видимый результат.** Панель открыта, сообщает необходимость разрешения
менять системные настройки; свет остаётся50,25 не показано как применённое.
Форма сообщения/перехода ещё не выбрана. Поздний grant сам не применяет старую
команду — принято ранее. Отказ ОС/частичный эффект дополнительно проверяются
по фактическому результату; для полного успеха их не считать принятым выбором.

## 10. Скрытые группы восстанавливаются через настройки

**1. Предмет и статус.** Видимость групп панели: сохранить, DEC-007.

**2. Как в Legacy.** Defaults всех групп=true. Slider, две строки числовых
кнопок, третья строка Auto/+/−, вложенные+/− и строка checkbox настраиваются.
Settings находится вне этих групп; hint зависит от slider/трёх строк,
даже если checkbox виден. E09/E11/E12, e9f944aa.

**3. Предложение и почему.** Сохранить группы и доступ к восстановлению.
Не связывать скрытие переключателя с изменением его сохранённого значения.
Не фиксировать Legacy размеры/цвета/число пикселей как макет Compose.

**4. Экран и исходное состояние.** Main открыт; право менять соответствующие
настройки доступно. Для варианта checkbox close on select уже включён.

**5. Действия по порядку.** А: пользователь открывает Settings значком,
скрывает slider и все три строки, нажимает Back; затем снова открывает Settings,
показывает slider и возвращается. Б: пользователь скрывает только третью
строку. В: пользователь скрывает только строку checkbox и возвращается на main.

**6. Видимый результат.** А: подсказка «Элементы управления скрыты. Включите
их в настройках» и доступ к Settings; после восстановления slider виден,
выбор сохраняется. Б: нет Auto и вложенных+/−, даже при отдельном show+/−=true.
В: переключатели не видны, close on select остаётся включён; его можно выключить
в Settings. Текст подсказки предлагаемый, форма/точная редакция ещё не выбраны.

## 11. Повторный вход показывает одну панель; Back не выключает свет

**1. Предмет и статус.** Одна пользовательская панель и уход с неё:
сохранить назначение, DEC-007; отсутствие повторной команды уже принято.

**2. Как в Legacy.** Manifest singleTask; value widget и область открытия
Main в уведомлении посылают Activity intent. Исторический комментарий объясняет
борьбу с повторными экземплярами при многократном нажатии уведомления.
Back вызывает finish, service им не останавливается. Resume может повторить свет.

**3. Предложение и почему.** Сохранить одну панель и независимость действующей
сессии от её закрытия; убрать командный эффект повторного входа по принятому
контракту. Конкретный launchMode новой версии выбрать позже.

**4. Экран и исходное состояние.** Main открыт; действующее затемнение-25,
срок16:00. Быстрые controls/value widget доступны; события происходят15:00–15:02.

**5. Действия по порядку.** Пользователь уходит Home, нажимает текст value
widget для открытия Main; в независимых вариантах нажимает значок BCD либо
область открытия Main в уведомлении, затем системный Back. В15:02 пользователь
ещё раз открывает BCD значком.

**6. Видимый результат.** При каждом входе одна панель; после Back пользователь
видит предыдущий экран. Затемнение-25 и срок16:00 сохранены, повторный вход
не начинает новый срок. Если ОС фактически остановила сессию либо её срок уже
обработан, BCD показывает фактическое состояние и не оживляет её.

Техническая заметка: singleTask может убрать Activities выше Main; возврат
внешним входом из незавершённого редактора требует проверки в будущем плане.
Данным случаем не выбирается потеря/восстановление черновика.

## 12. Поддержка начинается с Android8 / API26

**1. Предмет и статус.** Платформенная граница выпуска: готовая конфигурация,
DEC-028; явное отличие от Legacy.

**2. Как в Legacy.** Текущая сборка задаёт min21/compile33/target33 и Java17.
Новый проект задаёт min26/compile37/target37, Kotlin/Compose/Material3,
bytecode17/JDK21. Это чтение конфигурации, не проверка будущей BCD.

**3. Предложение и почему.** Использовать подготовленный стек без нового
обновления зависимостей. Честно принять прекращение поддержки API21–25
новой версией; это проектный выбор, не доказанная техническая невозможность.

**4. Экран и исходное состояние.** А: устройство Android7.1/API25 с Legacy.
Б: поддерживаемое устройство API26 или37 после корректной установки новой версии.

**5. Действия по порядку.** А: пользователь пытается установить/обновить
приложение новым APK; ОС проверяет minimum. Б: пользователь нажимает значок BCD.

**6. Видимый результат.** А: новая версия несовместима и не устанавливается
обычным путём; существующая Legacy не превращается в работающую новую версию.
Наличие прежней версии в магазине зависит от будущего выпуска и не обещается.
Б: должен открыться работоспособный main; это требование будущей проверки,
не заявленный результат нынешнего template smoke.

## 13. Управление светом не ждёт подключения к сети

**1. Предмет и статус.** Offline manual/negative/Auto: сохранить, DEC-028.

**2. Как в Legacy.** Командная цепочка E05 пишет системные настройки и
управляет локальным overlay; сетевого ответа внутри неё не найдено.
При запуске могут отдельно работать Billing/Ads/RemoteConfig.

**3. Предложение и почему.** Не ставить команды света в зависимость от сети
или результата рекламы/проверки магазина. Не менять принятую коммерческую политику
и не обещать отсутствие сети во всём приложении.

**4. Экран и исходное состояние.** На поддерживаемом устройстве main открыт,
интернет отключён. Для будущей проверки доступны необходимые разрешения
и ОС принимает команды; это техническое условие результата, не новая опция.

**5. Действия по порядку.** Пользователь нажимает25, затем-25, затем Auto;
BCD выполняет каждую команду локально, ОС принимает соответствующую настройку.

**6. Видимый результат.** Последовательно manual25, затемнение-25, затем Auto
без затемнения, без ожидания подключения. В default255 raw63/12 для первых
двух команд; физическая видимость/OEM и фоновые ограничения требуют будущих
реальных проверок. Невозможность получить доступ к ОС не выдаётся за сетевую ошибку.
